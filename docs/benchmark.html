Benchmark

El arnés rdd-bench levanta un AxumPlatform real en un puerto efímero, con tres rutas HTTP y un canal WebSocket de eco, y mide latencias y tasas desde clientes HTTP/1.1 keep-alive y tokio-tungstenite. Los números de esta página los escribe el propio arnés en docs/assets/benchmarks.json.

Rendimiento HTTP

Peticiones por segundo por escenario y nivel de concurrencia. Cada worker mantiene su conexión; la ventana es la misma para todos los niveles.

Latencia HTTP

Percentiles p50, p95 y p99 con concurrencia máxima ( conexiones). Se mide desde el envío hasta que el cuerpo completo se consume.

WebSocket: ida y vuelta

Eco de mensajes de 64 B, 1 KB y 8 KB. El cliente envía y espera el eco antes de medir el siguiente; el tiempo es el viaje completo.

WebSocket: rendimiento

Mensajes por segundo con una y ocho conexiones simultáneas.

Datos completos

Todo lo que dibujan los gráficos, sin redondear, para comparar entre máquinas.

Metodología

Los benchmarks dependen de la máquina. Compara siempre ejecuciones en el mismo equipo, con el mismo perfil de compilación y el servidor en local. No es un techo teórico: es el costo del enrutado, la cadena global, el parseo de cuerpos y la traducción de respuestas de rdd-axum. 
cargo run --release -p rdd-bench

# Ventana y volumen configurables:
RDD_BENCH_HTTP_MS=3000 RDD_BENCH_WS_MESSAGES=2000 cargo run --release -p rdd-bench

# Escribir el informe en otra ruta:
RDD_BENCH_OUT=/tmp/benchmarks.json cargo run --release -p rdd-bench

El informe se publica en docs/assets/benchmarks.json y esta página lo embebe al regenerarse con node scripts/build-benchmark-page.mjs. El código vive en crates/rdd-bench y los escenarios HTTP son GET /bench/ping, GET /bench/items/:id y POST /bench/echo; el canal es /ws/echo.
