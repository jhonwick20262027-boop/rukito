Inicio/CLI

Referencia de la CLI rdd

Comandos disponibles

New

rdd new  [--no-example]

Crea un proyecto nuevo con el árbol completo de secciones (§5).

  • Genera: Cargo.toml, rdd.toml, rust-toolchain.toml, rustfmt.toml, clippy.toml
  • Estructura de carpetas completa (§5)
  • Módulo tasks de ejemplo
  • Archivos de configuración .env y .gitignore
  • Opcional: --no-example para omitir el módulo de ejemplo

RF-002: `rdd new` DEBE generar el árbol completo de §5, incluido el módulo de ejemplo tasks, salvo --no-example.

G (Generate)

rdd g module

Genera un módulo con la convención NestJS (§5) y lo registra (§14.3).

  • Crea nueve carpetas con su mod.rs y los archivos nombrados en §5
  • Registra el módulo en src/modules/mod.rs y src/main.rs
  • Los nombres se singularizan: task-items → task_item para entities/dto/services/repositories, plural para controllers/constants
  • RF-001: El CLI DEBE generar el árbol de módulo y registrarlo

Run

rdd run

Ejecuta la aplicación del proyecto actual.

  • Carga la configuración rdd.toml
  • Inicializa tracing con RUST_LOG
  • Crea el runtime Tokio
  • Compone routes y middlewares en HttpApp
  • Abre el TcpListener y entrega a la plataforma

Scaffold y requisitos (RF-001 a RF-007)

Cada `mod.rs` generado DEBE documentar en su cabecera qué va ahí y qué API de `rdd` lo cubre. Las carpetas cuyo soporte llega en una fase posterior se generan como placeholder compilable, nunca como código que no compila.
IDRequisito
RF-001`rdd g module ` DEBE generar el árbol de módulo de §5 y registrarlo en src/modules/mod.rs y src/main.rs (§14.3)
RF-002`rdd new ` DEBE generar el árbol completo de §5, incluido el módulo de ejemplo tasks, salvo --no-example
RF-003Cada carpeta scaffold que sea un módulo Rust DEBE llevar un mod.rs; las que no lo son (docs/, prisma/migrations/, etc.) DEBEN llevar .gitkeep. Ninguna carpeta queda vacía.
RF-004
RF-005El singular de los nombres de archivo se calcula con regla fija: ies→y; ses/xes/zes/ches/shes→quita es; s final (salvo ss)→quita s; en otro caso, igual.
RF-006El scaffold NO DEBE generar código que dependa de macros o APIs aún no implementadas. En 0.1 services/ y entities/ son Rust plano; #[service] y #[aggregate] llegan en 0.2.
RF-007`rdd new` y `rdd g module` DEBEN producir un proyecto que pasa cargo check sin edits manuales, y tests/acceptance.rs DEBE pasar. Además cargo clippy --all-targets -- -D warnings y cargo fmt --all -- --check sin diffs.
