Inicio/CLI

Referencia de la CLI rdd

Comandos disponibles

New

rdd new <nombre> [--database sqlite|postgres] [--no-example]

Crea un proyecto nuevo con el árbol funcional mínimo de §5.

  • Motor predeterminado SQLite local (--database cambia la feature de la fachada, [database].provider y las URLs de respaldo)
  • Genera: Cargo.toml, rdd.toml, rust-toolchain.toml, rustfmt.toml, clippy.toml
  • Árbol funcional mínimo, sin capas placeholder (§5)
  • Módulo tasks de ejemplo y su migración migrations/0001_tasks.sql
  • Archivos de configuración .env, .env.example y .gitignore
  • Opcional: --no-example para omitir el módulo de ejemplo

RF-002: rdd new DEBE generar el árbol funcional mínimo de §5, incluido el módulo de ejemplo tasks, salvo --no-example.

G (Generate)

rdd g module <nombre>

Genera un módulo DDD organizado en cuatro capas (domain/, application/, infrastructure/ y presentation/) y lo registra (§14.3).

  • Crea solo las cuatro capas necesarias, sin carpetas placeholder; los tests unitarios quedan inline con #[cfg(test)]
  • Registra el módulo en src/modules/mod.rs y src/main.rs
  • El agregado usa el nombre singular (task_item.rs); las capas y los archivos de aplicación/adaptadores/presentación conservan el plural
  • RF-001: El CLI DEBE generar el árbol de módulo y registrarlo

Run

rdd run

Ejecuta la aplicación del proyecto actual.

  • Carga la configuración rdd.toml y .env
  • Inicializa tracing con RUST_LOG
  • Crea el runtime Tokio
  • Compone routes y middlewares en HttpApp
  • Abre el TcpListener y entrega a la plataforma

Migrate

rdd migrate [--database-url <url>] [--source <dir>]

Aplica las migraciones SQL versionadas de migrations/ como paso explícito antes de arrancar o desplegar (RF-188). El servidor no migra al arrancar.

  • Lee la URL de la variable indicada por [database].url_env en rdd.toml (por defecto DATABASE_URL) y el directorio de [database].migrations_dir
  • Crea el archivo SQLite si no existe; con SQLite la base vive en la raíz del proyecto y el .gitignore la excluye (RF-063)
  • Lleva el historial en _sqlx_migrations: volver a ejecutarlo no repite migraciones
  • Si falta la URL, termina con un mensaje que nombra la variable

Scaffold y requisitos (RF-001 a RF-007)

IDRequisito
RF-001rdd g module <name> DEBE generar solo las cuatro capas funcionales del módulo (§5) y registrarlo en src/modules/mod.rs y src/main.rs (§14.3)
RF-002rdd new <name> DEBE generar el árbol funcional mínimo de §5, incluido el módulo de ejemplo tasks, salvo --no-example
RF-003Cada carpeta scaffold que sea un módulo Rust DEBE llevar un mod.rs; migrations/, usada por rdd migrate, DEBE llevar .gitkeep sin el módulo de ejemplo. No se generan carpetas vacías ni capas placeholder.
RF-004Cada mod.rs generado documenta en su cabecera la responsabilidad de su capa. El generador NO DEBE crear carpetas vacías ni capas placeholder.
RF-005El singular de los nombres de archivo se calcula con regla fija: ies→y; ses/xes/zes/ches/shes→quita es; s final (salvo ss)→quita s; en otro caso, igual.
RF-006El scaffold NO DEBE depender de macros o APIs aún no implementadas. Las invariantes viven en domain/, los casos de uso en application/, los adaptadores en infrastructure/ y HTTP en presentation/.
RF-007rdd new y rdd g module DEBEN producir un proyecto que pasa cargo check sin edits manuales, y tests/acceptance.rs DEBE pasar. Además cargo clippy --all-targets -- -D warnings y cargo fmt --all -- --check sin diffs.
