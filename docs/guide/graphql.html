Inicio/GraphQL

GraphQL en rdd

GraphQL es una entrada opcional sobre el mismo HttpApp y el mismo contenedor: los resolutores llaman a los casos de uso y la identidad la siguen dejando los middlewares globales. No sustituye a REST; convive con él.

Activar la feature y montar /graphql

La fachada declara la feature graphql, que trae el motor, las macros y el montaje de la plataforma:

rdd = { version = "0.1", features = ["graphql"] }

El montaje va en main.rs, después de componer la app:

use rdd::AxumPlatform;
use rdd::graphql::{GraphqlHttp, GraphqlHttpConfig, Schema};

let schema = Schema::builder()
    .query(app_graphql::Query)
    .mutation(app_graphql::Mutation)
    .subscription(app_graphql::Subscription)
    .build()?;
let graphql = GraphqlHttp::new(schema).config(
    GraphqlHttpConfig::new()
        .path("/graphql")
        .explorer(true)
        .public_explorer(false)
        .max_depth(16)
        .authorize(require_session),
);

App::new()
    .module(tasks::module())
    .run_on(AxumPlatform::new().graphql(graphql), "0.0.0.0:3000")
    .await
  • GraphqlHttpConfig::new() ya deja /graphql, explorer activo, public_explorer(false) y profundidad 16; los setters existen para cambiarlo.
  • Un path vacío o sin / inicial, un max_depth de 0, un choque con una ruta HTTP, un canal, /mcp u otro /graphql impiden arrancar (RF-233, RF-242).
  • Sin la feature o sin .graphql(...), el router no cambia: /graphql responde el 404 del fallback.

El esquema es el tipo Rust

No hay SDL aparte ni codegen en build. Las macros publican los tipos y las raíces; snake_case se expone como camelCase, el doc comment se convierte en description y #[graphql(skip)] deja un campo fuera del esquema:

use rdd::GraphqlObject;
use rdd::graphql::{GraphqlContext, GraphqlInput, GraphqlStream, graphql_object};
use rdd::prelude::*;
use uuid::Uuid;

/// Tarea tal como la ve un cliente GraphQL.
#[derive(GraphqlObject)]
pub struct Task {
    pub id: Uuid,          // se publica como ID
    pub title: String,
    pub done: bool,
    // Un campo que no deba viajar se excluye con `#[graphql(skip)]`.
}

#[derive(GraphqlInput)]
pub struct CreateTaskInput {
    pub title: String,
}

#[graphql_object(query)]
impl Query {
    /// Tareas del dueño del token.
    async fn tasks(&self, ctx: &GraphqlContext) -> Result<Vec<Task>> {
        let session = ctx.ext::<Session>().ok_or(Error::Unauthorized)?;
        let svc = ctx.resolve::<TasksService>()?;
        let tasks = svc.list_of(session.id, None, None).await?;
        Ok(tasks
            .into_iter()
            .map(|task| Task::from(TaskResponse::from(task)))
            .collect())
    }
}

#[graphql_object(mutation)]
impl Mutation {
    async fn create_task(
        &self,
        ctx: &GraphqlContext,
        input: CreateTaskInput,
    ) -> Result<Task> {
        let session = ctx.ext::<Session>().ok_or(Error::Unauthorized)?;
        let svc = ctx.resolve::<TasksService>()?;
        let task = svc.create(session.id, input.title, None).await?;
        Ok(Task::from(TaskResponse::from(task)))
    }
}

#[graphql_object(subscription)]
impl Subscription {
    async fn task_changed(
        &self,
        ctx: &GraphqlContext,
    ) -> Result<GraphqlStream<Task>> {
        // … una cola alimentada por el hub de §10.5
    }
}
  • El tipo GraphQL vive en presentation/ y se construye desde el DTO (TaskResponse); publicar el agregado directamente acoplaría el esquema al dominio.
  • En un impl de raíz cada método es async, recibe &GraphqlContext y devuelve rdd::Result<T>; en subscription, GraphqlStream<T>.
  • Un tipo o una firma no soportada es el diagnóstico RDD0501; un nombre duplicado o reservado (__) es RDD0502.
  • SchemaBuilder::build valida el esquema al arrancar: dos raíces con el mismo campo, un tipo repetido con definiciones distintas o una raíz sin campos fallan antes de abrir el socket.

Consultar sin explorer

Las operaciones son un POST JSON con {query, operationName?, variables?}. La cadena global ya corrió, así que el guardián solo confirma la identidad que dejó el JWT:

TOKEN=$(curl -s -X POST localhost:3000/auth/login \
  -H 'content-type: application/json' \
  -d '{"email":"admin@example.com","password":"una-clave-larga"}' \
  | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')

curl -s localhost:3000/graphql \
  -H "authorization: Bearer $TOKEN" \
  -H 'content-type: application/json' \
  -d '{"query":"{ tasks { id title done } }"}'
{
  "data": {
    "tasks": [{ "id": "…", "title": "comprar pan", "done": false }]
  }
}

Los errores de GraphQL viajan con 200 en errors, como manda la especificación del lenguaje; solo los errores de transporte son 4xx. message nunca filtra el detalle interno: se registra con tracing.

Suscripciones por SSE

Las suscripciones viajan por text/event-stream, no por WebSocket. Un POST con Accept: text/event-stream devuelve event: next por cada evento y event: complete al cerrar; sin ese Accept la respuesta es 406:

curl -N -s -X POST localhost:3000/graphql \
  -H "authorization: Bearer $TOKEN" \
  -H 'content-type: application/json' \
  -H 'accept: text/event-stream' \
  -d '{"query":"subscription { taskChanged { id title done } }"}'
event: next
data: {"data":{"taskChanged":{"id":"…","title":"comprar pan","done":false}}}

: ping

event: complete
data: {}
  • La suscripción exige un único campo raíz; el resultado se filtra por identidad en el resolutor, porque el hub es de todos.
  • No hay reanudación (Last-Event-ID se ignora) ni transporte WebSocket para suscripciones.
  • Si el cliente desconecta, la suscripción se cancela al cerrarse la cola y no queda tarea huérfana.

El explorer

GET /graphql sin query sirve una app Vue 3 + TypeScript embebida en el binario: sin CDN, sin recursos externos y con CSP propia. Incluye:

  • Editor CodeMirror 6 con resaltado y autocompletado GraphQL: sugiere al escribir y con Ctrl+Espacio; Tab indenta la línea o la selección y, con el desplegable abierto, acepta la sugerencia activa.
  • Árbol de esquema y documentación generados desde __schema, pestañas de variables y cabeceras, historial local y ejecución con Ctrl+Enter.
  • Suscripciones SSE con botón de detener; la petición va por fetch porque EventSource no admite POST.
  • Errores con locations/path, estado HTTP, tiempo y cuerpo JSON.

La introspección que carga el esquema también es una operación: necesita el Authorization: Bearer en la pestaña Cabeceras. La guía JWT en el explorer explica cómo pegarlo.

Producción: deja explorer(false) o GRAPHQL_EXPLORER=false. Con el explorer desactivado, una petición sin credenciales recibe primero el 401 del guardián y, ya autorizada, el 404. public_explorer(true) solo exime el documento HTML, nunca las operaciones.

Requisitos completos: RF-233 a RF-244 en la especificación (§10.9).
