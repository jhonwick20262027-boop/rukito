JWT en el explorer

El explorer se sirve sin sesión, pero cada operación —incluida la introspección que carga el esquema— pasa por el guardián. Sin un Authorization: Bearer válido, el panel responde 401. Esta guía obtiene el token y lo deja puesto en la pestaña Cabeceras.

1. Arranca el demo con /graphql

El demo necesita JWT_SECRET en .env; sin él no arranca. Con --explorer-token imprime un Bearer de preview firmado con la misma clave del servidor y sigue arrancando:

cargo run -- --graphql --explorer-token

# EXPLORER_TOKEN=eyJhbGciOiJIUzI1NiIs…
# Servidor escuchando en 0.0.0.0:3000
  • Copia solo el valor, sin el prefijo EXPLORER_TOKEN=.
  • La identidad sale de config/explorer_config.rs; la firma es la del servidor y caduca con JWT_TTL_SECS (3600 s por omisión).
  • Es una ayuda de desarrollo: imprime un JWT válido en la salida estándar. No lo uses en producción ni lo dejes en un log.

2. O obtén el token de un usuario real

Si prefieres probar con una cuenta (y sus tareas), registra y haz login por REST. La respuesta trae access_token:

curl -s -X POST localhost:3000/auth/register \
  -H 'content-type: application/json' \
  -d '{"email":"ana@example.com","password":"una-clave-larga"}'

TOKEN=$(curl -s -X POST localhost:3000/auth/login \
  -H 'content-type: application/json' \
  -d '{"email":"ana@example.com","password":"una-clave-larga"}' \
  | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')

Los resolutores leen la identidad con ctx.ext::<Session>(); por eso el token del login y el de --explorer-token se usan igual.

3. Pégalo en la pestaña Cabeceras

  1. Abre http://localhost:3000/graphql (usa tu PORT si lo cambiaste).
  2. Entra en la pestaña Cabeceras, junto a Operación y Variables.
  3. Escribe un objeto JSON con valores de tipo cadena:
{
  "Authorization": "Bearer <tu-token>"
}
  • El objeto se fusiona con Content-Type: application/json y Accept, que el explorer pone solo.
  • Cada valor debe ser una cadena; un número o un booleano dan error antes de enviar.
  • Si el JSON está mal formado, el panel lo dice y no hace la petición.

4. Recarga el esquema con el token

La introspección se lanzó al abrir la página, antes de que hubiera cabeceras. Pulsa el botón de recargar del encabezado —«Recargar el esquema con las cabeceras actuales»— o el de la pestaña del esquema. Cuando termine, el indicador muestra Esquema listo y el número de tipos; el árbol y el autocompletado ya salen del esquema real.

Si el token falta o caducó, el panel de esquema muestra el 401 en Problem Details. Pega uno nuevo y vuelve a recargar.

5. Ejecuta

Con el token puesto, escribe una operación y pulsa Ejecutar o Ctrl+Enter:

query {
  tasks {
    id
    title
    done
  }
}

Una mutación con variables usa la pestaña Variables:

mutation Crear($input: CreateTaskInput!) {
  createTask(input: $input) {
    id
    title
    done
  }
}
{
  "input": { "title": "comprar pan" }
}

El panel derecho muestra el estado HTTP, el tiempo, el tamaño y el JSON. Los errores de GraphQL llegan con 200 y errors; un 401 significa que el Bearer no llegó, caducó o el guardián lo rechazó.

6. Suscripciones

Una suscripción usa las mismas cabeceras y se abre como stream SSE. El explorer detecta el tipo por la palabra clave, envía Accept: text/event-stream y va pintando cada event: next; el botón de detener cancela la petición.

subscription {
  taskChanged {
    id
    title
    done
  }
}

El primer evento no aparece hasta que algo cambia: en otra terminal, crea o completa una tarea por REST con el mismo token. Si el token caduca a mitad del stream, la suscripción se corta: renueva el Bearer y vuelve a ejecutar.

Qué protege y qué no

ConfiguraciónEfecto
public_explorer(false) (framework)El propio documento HTML exige sesión; sin credenciales la respuesta es 401.
public_explorer(true) (demo por defecto)El HTML se sirve sin sesión; las operaciones siguen exigiendo el Bearer.
explorer(false)No hay UI: 404 tras autorizar (401 primero si falta la credencial).
authorize(require_session)Sin sesión no se ejecuta ninguna operación ni la introspección.

Producción: desactiva el explorer o, como mínimo, el acceso público; no arranques con --explorer-token; usa un JWT_SECRET real y rota los tokens con una vida corta. El explorer guarda el historial local con las cabeceras que pegaste: no uses una máquina compartida con un token de producción.

Más detalle: §10.9 (explorer y authorize) y §26.9 (demo con JWT) en la especificación.
