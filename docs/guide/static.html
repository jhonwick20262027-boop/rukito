Archivos estáticos en rdd

Servir un directorio del disco es otra entrada opcional sobre el mismo HttpApp: la resolución, la seguridad de rutas, el MIME, la caché y el SPA viven en rdd-static; el montaje en el router lo aporta rdd-axum. La cadena global —CORS, JWT, RateLimit— corre igual que para una ruta de la API.

Activar la feature y montar /site

La fachada declara la feature static-files, que trae el crate neutral y el montaje de la plataforma:

rdd = { package = "rdd-framework", version = "0.1", features = ["static-files"] }

El montaje va en main.rs, después de componer la app. La raíz se canonicaliza al construir StaticFiles y la configuración se valida antes de abrir el socket:

use rdd::{AxumPlatform, StaticFiles, StaticFilesConfig};

let files = StaticFiles::new("client")?.config(
    StaticFilesConfig::new()
        .mount("/site")
        .spa(true)
        .public(false)
        .dotfiles(false)
        .immutable("/assets")
        .authorize(require_session),
)?;

App::new()
    .module(tasks::module())
    .run_on(AxumPlatform::new().static_files(files), "0.0.0.0:3000")
    .await
  • Un directorio inexistente o que no sea una carpeta es un error de arranque, no un 404 por petición.
  • El montaje cubre el prefijo exacto, su barra final y todo su subárbol; las rutas literales del núcleo (/health, /tasks) conservan prioridad.
  • Un choque exacto con una ruta HTTP, un canal, /mcp, /graphql, /api-docs o su JSON, o dos montajes iguales o solapados impiden arrancar (RF-257).
  • Sin la feature o sin .static_files(...), el router no cambia: una petición a ese prefijo recibe el 404 del fallback.

Resolución y seguridad de rutas

La ruta se decodifica (%XX) antes de dividirla en segmentos, así que %2e%2e%2f cuenta como ../. Ningún segmento puede ser vacío, . o .., ni contener \, :, *, ?, ", <, >, | o caracteres de control; los que empiezan por punto solo pasan con dotfiles(true).

El candidato se canonicaliza y se exige que su ruta real siga bajo la raíz canonicalizada: un enlace simbólico que escape tampoco se sirve. Una ruta que no resuelve no revela si el archivo existe: handle devuelve None y la plataforma responde el 404 canónico del núcleo, sin repetir la cadena global (ya corrió en prepare).

El Content-Type sale de la extensión con mime_guess; los tipos textuales (text/*, +json, +xml, application/json, application/javascript, image/svg+xml) llevan charset=utf-8. El índice y los archivos fuera de los prefijos inmutables usan Cache-Control: no-cache; bajo un prefijo immutable la respuesta es public, max-age=31536000, immutable.

El ETag es fuerte y se deriva de tamaño y fecha de modificación, así que un cambio en disco se ve en la petición siguiente sin reiniciar el servidor. El fallback de SPA solo se aplica a rutas sin extensión y con Accept: text/html: nunca convierte una petición de API o de asset en index.html.

El demo: --static

example/todo-app --static sirve client/ en /site sobre el mismo servidor y el mismo contenedor. El modo se acumula con --mcp-http, --graphql y --openapi, y la política sale del entorno:

VariablePor defectoEfecto
STATIC_DIRclientDirectorio servido; debe existir al arrancar
STATIC_MOUNT/sitePrefijo literal del montaje
STATIC_SPAfalseFallback de SPA para rutas sin extensión
STATIC_PUBLICtruefalse activa require_session
STATIC_DOTFILESfalsetrue sirve archivos ocultos
cargo run -p todo-app -- --static
curl -sI localhost:3000/site/                     # 200 text/html, no-cache
curl -sI localhost:3000/site/assets/style.css     # 200 text/css, immutable
curl -s  localhost:3000/site/no-existe            # 404 Problem Details

STATIC_PUBLIC=true es una decisión del demo, igual que el explorer y el documento: la página se lee sin JWT y la API que consume sigue exigiendo el token. En producción se pone STATIC_PUBLIC=false y authorize protege el directorio.

Producción y límites

  • No hay hot reload ni watcher: cada petición lee el archivo del disco. Al editarlo basta con recargar el navegador; el servidor no reinicia ni empaqueta los archivos en el binario.
  • Los assets bajo /assets son inmutables por contrato: en desarrollo cambia el nombre del archivo o el prefijo si editas uno ya cacheado.
  • Sirve detrás de tu proxy con TLS; el framework no añade compresión ni rangos parciales en esta fase.
  • El cuerpo se limita con limits.body_limit_bytes y por encima se responde 413 sin tocar el disco (RP-006).

Requisitos completos: RF-255 a RF-260 en la especificación (§10.11).
